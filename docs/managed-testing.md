# Managed OPEN testing (Pi candidate)

The Pi OPEN pipeline uses the same central worker configuration for test owner, implementer and reviewer. The production selection is `openai-codex/gpt-6-sol` at reasoning `high`; source admission does not pin that identity for mock inference or other operator-configured Pi workers. Bounded tasks and legacy non-Pi executions keep their existing paths; an explicitly managed-testing ticket on a non-Pi harness is refused. This source change does not activate or change the operator's worker configuration.

Each Pi OPEN ticket's `## Testing plan` must declare `Broad regression: none`, or `Broad regression: required` followed immediately by `Command: <operator-approved command>`. The approved testing-workflow-v1 phase ticket uses its original `npm test` clause. Commands are ticket-owned, never supplied through the test tools; a broad run is admitted once per review round, after the reviewer records a READY/no-repair assessment and the current selected tests pass. Incomplete attempts consume the round's allowance.

The project supplies `.architect/test-runner.json` with schema 1, command `node`, empty `args`, test `directory` and `extension`. The managed tools accept only existing relative files under that directory. The broad `run.mjs` entrypoint is not a focused target. Different project runners require an explicit extension of the approved runner configuration, not agent-supplied commands.

The record under the workflow state directory (`managed-tests/<execution id>.json`) stores selection, per-target launches and elapsed outcomes, tested working-state digests, categorized review assessments, and checkpoint attempts. The execution result references and includes this record. A PASS requires matching current reviewer focused evidence and, when required, checkpoint evidence. A changed file/selection cannot inherit a previous PASS. READY, material FAIL, DECISION_NEEDED, INCOMPLETE and nonblocking suggestions are distinct; an unexplained initial test failure is not automatically expected-red. No retry-to-green, caching, sandbox, shell-wide detection or performance guarantee is implied.
