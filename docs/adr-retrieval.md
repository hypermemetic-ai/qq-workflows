# Shared ADR lookup (phase 52315bc8)

Two uses of **one** retrieval layer: `search_adrs` / `read_adr` for Architect planning, and `prepareCandidateSet` for Jev candidate comparison. Lookup relevance is not a decision, mandate or approval. There is no automatic publisher, scheduler, wakeup or third model-judgment stage.

## Committed corpus

The project's direct `docs/adr/` directory contains Markdown documents named `ADR-<id>.md` or `ADR-<id>-<slug>.md`. `<id>` is the first hyphen-delimited ASCII alphanumeric token after `ADR-` (e.g. `0007`); the optional readable slug is lowercase alphanumeric words separated by hyphens. Cite `ADR-0007` or the complete `ADR-0007-use-postgres` stem, **case sensitively** (no `.md` or path). A slug is advisory after unique-ID resolution; duplicate IDs, invalid ADR-named files, symlink ADRs and nested ADR-named files refuse the entire corpus. README, guides and historical evidence are not ADR documents. No status filter excludes superseded decisions.

`readAdrCorpus({projectRoot, revision = 'HEAD'})` resolves one commit and reads git blobs, never dirty worktree bytes. Each exact UTF-8 document carries `version: sha256:<hex>` and `sourceRevision: <commit>`. A non-ADR commit does not change `corpusHash`. `readAdr` pages the exact committed text (`offset`, `limit`, `nextOffset`, `complete`, at most 8192 characters per page); search excerpts are passages, **not full documents**. Pin `revision` explicitly when repeating a read across a moving HEAD. The operational index is derived, never an authority or publication target.

## Derived index and production wiring

`updateAdrIndex({stateDir, projectRoot, revision, backendFactory?})` materializes *only* committed ADR documents under `<stateDir>/adr-index/workspace`, indexes that dedicated root, and writes `<stateDir>/adr-index/index-receipt.json` after success. Receipts record corpus content hash, committed revision, config hash, backend identity and index time. No index work occurs for unchanged ADR hashes; the next deterministic publisher phase can invoke this retryable helper after exact committed ADR publication (this phase does not publish). `searchAdrs` defaults to read-only index lookup; `refreshIndex: true` requests a derived-state rebuild when missing/stale. Missing, stale, failed and empty-corpus states differ; missing/stale/failed lookups never become zero matches. A stale index is refused until refreshed rather than presenting passages as exact current excerpts. ZG's scanner-excluded `.zvec-grep/` index home remains under the dedicated workspace root across publication refreshes; receipts and candidate snapshots live outside indexed documents. The index is not the historical evidence index and ordinary worker search is unchanged.

Production adapter `resolveZvecModule` imports `@zvec/zvec-grep` by package name; when this repository cannot resolve that package, configure `QQ_ADR_ZVEC_MODULE` explicitly to the supported installed module or get an honest unsupported error. The repository does **not** declare the package in `package.json`; the inspected workstation has 0.2.1 globally installed, but a bare import from this checkout is currently unresolved. `createZvecBackend` uses `createZvecGrep({root: derivedWorkspace})`, plain `index({})`, and **one** direct `context({queries,limit,trace:true,fuse:false,autoUpdate:false})`. No embedding/model/endpoint/device override is passed: upstream uses its global/default configuration (and stored index schema); inspected 0.2.1 has a Qwen-family catalog but falls back to `local/potion-code-16m-v2` for a new index when no embedding is configured. Actual effective model/config and live quality are **not verified** here. The indexed model/schema is an operational concern for a production rollout. Bare ZG uses hybrid FTS/vector and rank-based RRF scores, **not Jina** and not similarity probabilities; `bin/zg-rerank.py` is a separate retained `jinaai/jina-reranker-v3.5` wrapper, deliberately not invoked (no extra GPU/model load or second stage). Its 20/5 defaults are not ADR ceilings. Direct context supports per-group limits above the MCP/daemon cap of 50; upstream adaptive route recall grows from 200 to at most 2000 **per FTS/vector route** before fusion. No score cutoff, calibration or recall guarantee is claimed. The production adapter contract suite tests actual resolver/create/index/context arguments with injection, not live model execution.

## Candidate policy and integration

`prepareCandidateSet({stateDir, projectRoot, evidence, revision, policy, backendFactory?, replay?})` requires selected *verbatim* phase-2 evidence with matching span hashes. Default switch: **0–50 eligible ADRs exhaustive** (all exact tuples, shadow retrieval for measurement only; shadow failure visible but never excludes); **>50 selective** search over evidence, always union every canonical explicit ADR reference (unresolved references warned), lift chunk hits to whole committed ADR tuples, dedupe with stable explicit-first ordering. Defaults: at most 8 groups of 4000 characters; per-group request `min(n, max(10, min(ceil(n * 0.5), 500)))`. These are **tuning parameters**, not measured recall; caller can revise the bounded policy. Budget/text deferrals, per-group requested/returned/saturation, 2000/route bound, source revision, index receipt and nonexhaustive coverage are returned. Unretrieved ADRs are not classified unrelated. Jev's 0.4 positive-class routing is unchanged and never applied to RRF scores. Failed above-50 retrieval returns incomplete/retryable, not an empty successful candidate set; a true empty corpus is valid.

Candidate identity/version snapshots reside in `<stateDir>/adr-jev/candidates`, keyed by ADR-only corpus hash, exact selected evidence/query, retrieval policy and index config. Replay returns actual previously selected tuples (no ranking determinism promise). `runAdrCurationComparison` composes retained manifest → selection → candidate policy → comparison → result packet. Exhaustive/filtered/deferred candidate coverage is passed to both `compareCandidates` and `buildResultPacket`; provider/cache/source integrity, pending obligation, and authoring/publication authority remain unchanged. No corpus fixtures with invented architectural decisions are shipped outside `tests/`.

No deployment or runtime acceptance was performed in this phase. Remaining work: deterministic Architect-text publication, obligation disposition, post-landing curation delivery/recovery and integrated runtime acceptance.
